2. Five findings that changed the design

  1. AppArmor enforces explicit deny rules even in complain mode, silently. Proven on isle-core with a probe profile. The first template was "allow everything, then deny a list", so warn-only would have bitten without a log line. The template is now an allow-list; complain keeps only docker's own stock denies, so a complain profile never denies more than every container gets today.
  2. Swarm services cannot carry a profile. docker stack deploy drops security_opt. On the server route the only MAC lever is the node-wide docker-default profile, which the daemon leaves alone if one is already loaded and which the parser can replace live. The renderer now writes it as the union of the stack's pieces, with docker's stock copy alongside for the revert.
  3. The escape test had never consulted AppArmor. Under the full confinement it blocked 14 of 14 with zero AppArmor decisions; dropped capabilities, seccomp and the read-only root did all the work. A profile-only pass now measures the profile's own share.
  4. The worker seccomp list broke python on alpine. Exactly one syscall was missing, open, which musl's loader uses. The backend image is alpine-based, so this would have taken the backend down on first attach. Found by the new log mode, fixed, and re-proven.
  5. A path-based profile cannot tell a bind of the host's files from the image. Reading the host's /etc/shadow through a bind mount is not AppArmor's to stop; it is user-namespace remapping's (your decision D1) and the mount policy's.

4. How the rings react to module deployments

The policy is meant to follow the apps up and down. Here is exactly what happens today at each event, and what does not happen yet.

The agent applying them at install is the isle-side phase, not built. Today nothing re-renders automatically.Modules are not containers; they run inside the backend. The module's stanza folds into the backend's profile (network and capabilities union; writable stays the backend's). All 59 stanzas are identical today, so nothing widens. Reaction to deployments is still manual: rendering and applying happen when someone runs pol prod apply, pol deploy harden or the isle's install hook. Making admission and put-away trigger the render is a later piece, and on the swarm the profile is node-wide anyway.

5. Two routes, two shapes of the same rings

Polari App deployment (the isle)

Installed from debs. The isle agent starts every app as its own plain docker container, so every app carries its own AppArmor profile and seccomp list. Hardware apps get a KVM guest with passthrough of what the hardware map assigns, under libvirt's per-VM profile; the hardware agent tier reaches the kernel and devices. The network ring is the agent's own firewall. This is the only route where per-app confinement and hardware access exist.

State: the union baseline and 65 per-app profiles loaded in complain on isle-core; per-app attachment is isle-core's half.

Docker Swarm deployment (the server)

The lean or full stack as swarm services. A service cannot carry a profile, so the MAC ring is one node-wide profile shared by every container on the node; seccomp can only be set for the whole daemon; the app-surface ring lives in the stack file. Modules run inside the backend and share its profile. No KVM guests, no device access, ever. Hardware apps still install, for development, and the user is told.

State: rendered and dry-run on econ-core; loading needs your sudo on pol-core and econ-core. Nothing on the public server.

On the rule "hardware modules cannot run on swarm": before today the only implementation was a conform lint (hardware kinds must declare the hardware agent tier). Nothing at admission or on any page said so. Per your ruling it is now a notice rather than a block, carried by POLARI_DEPLOY_ROUTE (set to swarm in the lean and prod stacks; isle-core is asked to set isle) through the registrar, the API, the CLI and the download card. It has not been seen live yet, since the core image was not rebuilt today.

Baseline audits, before any apply: pol-core partial 10/7/3, isle-core open 12/13/1, econ-core partial 9/8/3 (pass / fail / skip). The common fails: no user-namespace remap, root inside containers, writable root filesystems, empty DOCKER-USER, ufw inactive, sshd on all interfaces, no auditd.

Seven bugs in the test tooling were found and fixed on the way, each of which had made an earlier "proof" vacuous: a socket probe that hung forever, three probes that needed a python the image lacked, a lost exit status, a parser cache that silently skipped a reload, a render flag that left the fixed pieces in complain, wrong errno semantics, and a noexec tmpfs. The 2026-09-10 "14 of 14 blocked" is re-read as: the container flags blocked 14 of 14; the profile's own share was unmeasured until today.
