Rulings folded in today

ssh is for permission groups

No root over ssh in a secure posture. Named groups are allowed in, each with its own sudo command list. Dev posture may enable root over ssh, key-only, from the isle subnet, time-boxed. The audit checks both, and every device gets one reading: secure, dev until a time, or unsecured.

Dev mode versus production mode

An install is one or the other, recorded in a posture file and the instance env. Dev mode carries the standing warning that any connection to systems that are not your own is extremely dangerous. It shows in the notice bar, in the setup door, and in the CLI.

Development postures never leave the isle

Six boundary invariants written into the plan: inbound stays closed off-isle, nothing binds upstream interfaces, passwords never return, no key material leaves, refused on production routes, federation doors untouched. Design only, not built.

How to look for yourself

The home lean stack on pol-core serves the current dev branch. From the suite checkout:

pol prod status                       # the stack and its addresses
pol apps status gears --form access --from <api url> --insecure
pol apps access gears --flavor offline --from <api url> --insecure -o gears-access.deb
pol deploy inventory isle-core        # the machine's ssh surface and permission levels
pol security os audit                 # this machine's rings, warn-only reading

In a browser: the Downloads page under both tabs, the isle topology's ssh panels, the security overview and the threat simulations, and the notice bar. None of these were seen in a browser today because the Chrome extension was not connected, so the first browser pass is yours.
